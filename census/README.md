# Game-code censuses (PLAN step 2a)

Generated by `tools/census/*.py` from the `naming` tree at commit
`2efa6b43548fed253fafdee4d22c8d61d506acde` (naming fold 12), read through
`git cat-file` (never the working tree). Every TSV starts with `#` header lines
giving the census, source, commit and generator, then one row per site. The
common columns are `file line symbol image lib category`.

- `image` is one of main, title, insmenu, normal, factory or insect. A header
  row lists every image whose units include that header.
- `lib` is `sdk`, `library` or `game`:
  - `sdk`: path `src/main/sdk`, or a MAIN address in the SDK band
    0x108000–0x140000, the libkernl island 0x446000–0x448000, or the sdremote
    gcc island 0x165608–0x1660D4.
  - `library`: path `libc`/`lib*`/`gcc`, or crt0 + the MSL C++ runtime at
    0x100000–0x108000.
  - `game`: everything else.

Re-run everything with:

    python tools/census/run_all.py --source ../RGDecomp --rev <commit>
    python tools/census/run_all.py --source <extracted tree> --rev WORKTREE

Each script also runs on its own, with the same `--source/--rev/--out` options.

**x64 censuses (P7) are separate:** `tools/census/x64_census.py`, `x64_probe.py`,
`x64_ptr32_trial.py` and `x64_infra.py` read the *ingested port tree* (game/,
overrides/, missing/, src/), not a snapshot. They write to the scratch dir
`build/x64-probe/`, not here. Results and the migration plan are in docs/X64-PLAN.md.

**Scope.** These are registered linked units only:

- MAIN: `config/cunits.txt` (17,516 units).
- Overlays: `config/ocunits/*.txt` (title 97, insmenu 365, normal 659,
  factory 409, insect 744).

Each unit maps to a file the way `rgd.src_path()` does: the sorted `.c` files
first, then the `.cpp` files. A `config/hosted.txt` guest maps to its host's
file. That gives 19,760 files, with 0 units unresolved
(`unresolved_units.tsv`), plus the 9 `include/` headers they reach. Of the
19,777 `.c`/`.cpp` files on disk, 17 unregistered drafts and probes are
ignored. Generated data sources (`src/main_data/**`, from data2c) are scanned
when a snapshot has them. **This snapshot has none:** naming last merged MAIN
at 817e31bc, which is before data2c d784320c and the s88m de-asm work. Re-run
on the clean snapshot. Comments are blanked before matching. String contents
are blanked too, except in the `context` columns.

Files and units are nearly 1:1 (one unit per file; 30 hosted guests share
their host's file), so "files" below also means units.

**Limits.** Instructions are classified by mnemonic only; `jr` counts as a
return. A block's `body` does not say whether it reads or writes C locals by
register name.

## vcalls.tsv: 3,447 sites in 1,671 files (game 3,433; library 14)

By image (game):

| Image | Sites |
| --- | --- |
| main | 3,135 |
| normal | 149 |
| insect | 108 |
| factory | 41 |

There are 2,605 `dummy_vcall` sites (every virtual is a placeholder such as
`v12`, `d3`, `f128` or `slot1C`) and 828 `named_vcall` sites, across 1,909
distinct (file, class) views.

Columns:

- `cls`, `method`: the class and the virtual called.
- `slot`: the 0-based index after single-inheritance resolution (a base's
  slots come first, and an override keeps the base's slot).
- `slot_byte`: `8 + 4*slot`.
- `vptr_off`: the data bytes before the first virtual.
- `obj_off`: the constant from `(Cls *)((u8 *)p + 0xNN)` receivers.
- `access`: arrow or dot.
- `class_how`: how the class was found. 2,460 by declaration, 662 by cast,
  286 inferred from a unique owner, 39 ambiguous.
- `layout`: flags, e.g. `data-after-virtual` or `via-base`.

**Finding: the mwcc vtable has an 8-byte header.** 1,045 sites call a
virtual whose name encodes a hex byte offset (`v5C`, `f128`, `slot1C`, ...).
All of them satisfy name = 8 + 4·slot. Only 2 fit 4·slot, and 12 differ
(non-numeric names such as `vA`/`vf`). Another 1,351 names are the decimal
slot index itself. The P0 probe still has to confirm what the 8 bytes are and
where `vptr` points, but transform 3 can use `slot_byte` directly.

**Limits:**

- `vptr_off` is a cfront-style guess. 765 sites use classes with data
  members declared *after* the virtuals, which mwcc may lay out differently.
- Name-only override matching ignores overloads.
- Multiple inheritance is flagged, not resolved.
- Calls made with a bare `vN()` inside member bodies are not counted.
- Calls on non-pointer objects (`dot`) may be devirtualised by clang.

**Game rows by severity:**

- **abi, 5,486 rows:**
  - `call_count`: 2,351 call sites that pass a different number of
    arguments than the definition takes, calling 1,062 distinct callees.
    The worst is `UiMoveWidgetUniform_290f50`, with 174 calls of 6 args
    against a 5-param definition.
  - `count`: 1,548 declarations.
  - `ret`: 1,364. Of the `ret` mismatches, 783 symbols are declared as
    returning a value while the definition returns `void`. For example,
    callers read `f32 NavNodeDistSq_3118d0`, but it is defined
    `void (s32, s32)` and leaves `$f0` from a tail call. These need the
    definition fixed, not the callers.
  - `param` float/int/64-bit/struct: 160.
  - `varargs`: 63.

  Together these involve 1,687 symbols, plus the 1,062 callees above.
- **type, 21,668 rows** (ptr vs int, 5,448 symbols). Harmless on i686, but a
  compile error under one unified `game_protos.h`. Unify toward the
  definition or the majority.
- **sdk, 1,866 rows.** The definition is an sdk/library unit, often an asm
  placeholder `void f(void)`. Check these against the real SDK prototype in
  `sce/`.
- **addronly, 479 rows.** Only the function's address is taken (callback
  tables).
- **asmdecl, 30 rows.** `extern void f(void)` placeholders used only by asm
  bodies.
- **check, 2,518 rows** (`arity_file`). These disagree with
  `config/arity_inferred.txt`, which is only 97% accurate. 6,795 of its 6,863
  names are current symbols.

The plan's known example is caught: `ObjRecGetLiveObject` has one "1 vs 2"
row and three "3 vs 2" rows, plus 223 type rows.

**Limits:**

- The parser is regex-based. pycparser cannot read this corpus, which mixes C
  with mwcc C++, `asm` functions, `extern "C"` blocks, `__attribute__` and
  local classes.
- There is no preprocessor, so macro-generated prototypes are missed.
- Types reduce to classes (void, int, int?, ptr, f32, f64, i64, i128,
  struct). Small-int width and signedness are ignored.
- Typedefs resolve one level, per file.
- C++ member functions and calls through function pointers are skipped.
- When several static definitions share a name, the same-file one wins, then
  the same image, then MAIN.

## div_sites.tsv: 218 sites in 110 files (all game)

By image:

| Image | Sites |
| --- | --- |
| main | 181 |
| insect | 32 |
| normal | 4 |
| factory | 1 |

There are 116 `%`, 100 `/` and 2 compound sites. 214 are typed `int` by a
cast or declaration, and 2 are `unknown`. 842 float divisions were dropped:
577 by literal or cast, and 265 by a same-file f32/f64 declaration of an
operand name.

Typical divisors are `Rand() % n`, `x / e->bsize`, `% cnt`, and averages
`sum / grp->n`.

**Context.** The matching build uses `-pragma divbyzerocheck on` (and 241
files repeat it). Retail `asm/main.s` has about 480 `break` instructions
against about 665 `div`/`divu`, so a zero divisor most likely already trapped
on retail. On x86 the new risks are `INT_MIN / -1`, which traps there but not
on MIPS, and any divide without the check.

**Limits.** The float test is name-based per file, so an int `n` in a file
that also declares an `f32 n` is dropped. Divisors behind macros are assumed
constant only if they are ALL_CAPS.

## Shared method and limits

- `tools/census/snapshot.py` reads the commit, applies the registry rules
  above, strips comments (keeping line numbers), and finds top-level
  function and class bodies with a brace walk. That walk treats
  `extern "C" {` and `namespace {` as transparent and blanks preprocessor
  lines first.
- `symbol` is the enclosing function (or the unit name at file scope).
  Lines inside conditional-compilation branches are all scanned. There are
  about 40 `#if K*` blocks in a few hand-split files.
- `asm_only_unit` lists symbols, not files. A symbol is treated as part of a
  unit, not missing, when it is an interior entry of a multi-entry unit:
  either inside the unit's Ghidra span, or named in its source.
- The `platform_*.tsv` files in this folder come from a different census
  (another agent's) and are not described here.
