# Native renderer (`src/native/render`)

PLAN.md D9 ("100% native, no emulation") and "Native end state": the shipping exe draws
through a native renderer driven by the game's own render API. The emulated
VIF / VU1 / GS / GPU-exact path (docs/GPU.md, docs/VU.md) is bring-up scaffolding and the
verification oracle; it is not optimised further. This document is the design, the
reverse-engineering record of the dominant VU1 program, and the lane's checkpoint log.

Lane started 2026-10-17. Build tree `build/nrender-i686` (`tools/native/render_build.ps1`,
configured like `build/perf3d-i686`, `-j 4`). Scratch data: `out/nrender/` (captures,
corpora, listings; game data, never committed).

## Why the model program first

docs/PERF-3D.md "Data for the native renderer": EE game code is 1-3 ms per field; the rest
is the emulated pipeline. One VU1 program family (retail MPG packet 0x436CB0, MSCAL 0x320,
entries 0x328/0x330) does 93-95 % of all VU1 work in every scene, and its output is most of
the GS primitives (textured, blended triangles: the most expensive GPU category). Natively
drawing what that program draws removes, for those meshes, the VIF unpack, the VU1
interpretation, the GIF/GS vertex queue and the GS-exact raster at once.

## Architecture

```
 game render code (decompiled)            native lane
 ─────────────────────────────            ─────────────────────────────────────────────
 ModelDraw / ModelDrawSorted
   ModelPrepareDraw (matrices, bones)
   ModelEmitDrawPackets ─────────────►  override: per mesh, if its program variant is
   ModelQueueSortedPackets                native: record {mesh packet, material, item
                                          packets, variant} in the frame's scene list and
                                          put a 3-qword MARKER where the MSCAL + mesh call
                                          was (the DMA chain keeps its order)
 GfxEndFrame: DMA chain ──► VIF1 ──► (tap: VU1 constant snapshot into the record when the
                                      marker passes; transition only, see below)
                         ──► GS worker ──► gpu_core: marker hook ──► native draw
                                                     (same targets, same order as the
                                                      emulated primitives around it)
```

### Coexistence with the emulated path (transition)

* **Order**: a native mesh replaces only its `MSCAL 0x320 + CALL mesh` pair in the DMA chain
  with a marker (DMA CNT + VIF DIRECT of one A+D write to an unused GS register,
  `GS_NATIVE_MARK` = `0x7E`, value = record id; `src/ps2/gs` calls `hooks.native` for it).
  Everything else (camera/light/object packets, the material's GS register packet, 2D,
  effects) is untouched, so the GS register state at the marker is the material's, and the
  native draw lands between the same emulated primitives as the original one (checked:
  `RG_RENDER=verify` frames are bit-identical to `emu`).
* **State**: material state (FRAME, ZBUF, TEST, ALPHA, TEX0/1, CLAMP, FOGCOL, XYOFFSET,
  SCISSOR, FBA) comes from the GS registers at the marker; the native handler first applies
  the register writes the skipped program would have made (PRIM, PRMODE = 87.x, FOGCOL =
  qw41). Per-draw constants come from the record: in the transition they are snapshotted
  from VU1 data memory when the marker passes the VIF (a tap on VIF1's PATH2 sink, exactly
  what the microprogram would have read); the end state fills the same fields from the
  game's camera/light/object structures (`DrawPktBuildCameraMatrix`, `CameraWriteViewPacket`,
  `LightStateWritePacket`, `VifPktUploadMatrix`, `ModelBuildSkinMtxPacket` sources).
* **Side effect the game reads**: the Z-scale output pieces keep a screen-space min/max of
  every vertex in VU qw98/qw99, and the game reads it back (the character offscreen
  composite, `ModelDrawOffscreenCompositeMaybe_16aac0`, sizes each part's composite rectangle
  with it; without it every character vanished). The tap merges the same min/max for
  native meshes (`bbox_update`, CPU transform of the mesh's vertices).
* **Targets**: native draws render into gpu_core's render targets (colour RGBA8 holding GS
  bytes, depth z/2^32 in D32 or in the zrov R32 view) and mark the scissor rectangle dirty
  like a batch, so coherence (write-backs, read-backs, display) is unchanged.
* **Fallback**: meshes whose program variant or packet layout is not covered keep the
  original packets; the decision is per mesh at record time.

### Native pipeline rules (non-bit-exact by design)

* Transform/colour/fog/UV in the vertex shader from raw quantised attributes (the VU math),
  clip-space output with hardware clipping: the VU clipper (0x2620, 614 pairs) and the
  guard-band/ADC logic of the output pieces have no native counterpart. Screen x/y are
  truncated to 1/16 pixel and Z to an integer like the GS's ftoi4 input.
* Back-face culling (output pieces 0x43C2B0 / 0x43D110) = rasterizer culling: a triangle is
  culled when its screen area (even-strip winding, GS y down) times qw111.z (object
  handedness) times (87.y & 0x1000 ? -1 : 1) is positive. Lists match the program exactly;
  in strips the program also leaves ~70 % of the even-parity back faces uncull (a MAC-flag
  timing effect of its pipelined loop, render_nmcheck's table), which native culls.
* Textures: level 0 decoded once into RGBA8 (CLUT/TEXA applied, `CS_decode`), cached by
  content (FNV of each source page, cached per mirror stamp, plus a CLUT content hash), and
  sampled with a hardware point/bilinear sampler (REPEAT/CLAMP; region modes counted as
  unsupported).
* Blend: GS `(A-B)*C>>7+D` as dual-source blending (the shader outputs F = As/128 or
  FIX/128; coefficients a + bF per colour); As > 0x80 is clamped to 1.0, C = Ad is
  approximated (both counted).
* Depth: GEQUAL/GREATER on z/2^32 like the emulated path; native depth is float-interpolated,
  so native draws carry a 2-unit bias toward "far" (DepthBias -2, or -2/2^32 in the zrov
  shader) so coplanar emulated draws over native surfaces still pass their test.

## The model program (reverse engineering record)

Tools (all in `tools/native/`, documented under "Tools"): `rg-nr-vutrace` replays a retail
VIFCAP1 capture pair by pair and writes per-pc coverage, per-run piece tuples and a corpus of
(VU1 memory before, PATH1 packets after) per batch; `render_vucov.py` names the resident
pieces and writes coverage-annotated listings; `render_vifdump.py` lists the VIF stream.

Census on the retail captures (cutscene `C_v09002`, battle `C_v24804`): the program is
assembled from pieces at fixed VU addresses, chosen per mesh by `ModelEmitDrawPacketsMaybe`
(`info[0..5]` = `D_00491280` table entries: head/kind/tail from `VuMicrocodeTableInit`,
decode by LOD, colour by `k4`, output by `k5`):

| VU address | role | pieces seen (retail packet, pairs) |
| --- | --- | --- |
| 0x320 | head: batch header, GIF tag templates, calls the others | 0x436CB0 (87) |
| 0x960 | decode: dequantise; skinning (jump table by header 1.w: 0 one bone, 2 two, 4/6 four) | 0x4392C0 rigid (27), 0x4393B0 skinned (216) |
| 0x39D0 | kind: UV scroll / environment map | 0x43E980 (19), 0x43EA30 (52) |
| 0x10E0 | colour: constant, vertex colour, directional lights | 0x43A620 (26), 0x43AEC0 (73), 0x43A700 (44) |
| 0x2620 | clipper (when qw81.x bit 1): polygon clipping in clip space, emits fans | 0x4371D0 (614) |
| 0x1900 | output: screen transform, fog, STQ, colour clamp, XYZF2, GIF kick; variants add Z scale/clamp + bbox, guard-band ADC, back-face ADC | 0x43BC90, 0x43BF60, 0x43C2B0, 0x43CA90, 0x43CD40, 0x43D110 |

Per-run share (pairs): the 0x436CB0 head family is 92-97 % of all VU1 pairs in both
captures; the other heads (0x441660, 0x4425F0) and the runtime program at 0 the rest.

Constant block (VU qwords; who writes it):

| qw | content | written by |
| --- | --- | --- |
| 0-19 | GIF tag templates, Z max (1.y), projection rows 4-11, screen params 16-18, register tag 19 | `CameraWriteViewPacket` |
| 24-28 | view matrix | `DrawPktBuildCameraMatrix` |
| 30-51 | lights (dirs 30-32, colours 33-37), colour clamp 39, fog 40, FOGCOL A+D 41, material colours 42/43 | `LightStateWritePacket`, model info |
| 60-63 | object matrix | `VifPktUploadMatrix` (+ MSCAL 0: VU program at 0 computes 64-66 normalised rotation, 68-71 screen matrix, 72-75 clip matrix, 100-102 lights in object space, 111.z handedness) |
| 76-81 | batch out offset/skin flag, position/normal/UV scales, flags (81.x clipper, 81.w alpha) | model info packet (`mdl->v14`) |
| 82-88 | colour multiplier/add, vertex tag template, PRMODE (87.x), flags (87.y), Z scale (87.z), UV scroll (88) | material packet |
| 900+ | bone matrices (rows 900+2i .. 903+2i) | `ModelBuildSkinMtxPacket` |

Batch (at TOP): header qw0 = (PRIM, count, NLOOP|EOP, normal offset), qw1 = (UV offset,
colour offset, skin offset, skin jump); positions V3-16 (qw per vertex), normals V3-8, UV
V2-8 unsigned, colours V4-8 unsigned, skin records 2 qw (bone indices x2, weights /255).

Per-vertex math (`nr_vu1_batch`): p = int16/32768 * qw77 (skinned: sum of w_k * M_k * p);
uv = uint8/32768 * qw79 (+ qw88, or env map); colour = mat * vcol/128 (mat = qw82' * qw42 +
128 * qw83, or qw82' * qw43 when 87.y & 0x200), or lights; clip = qw68..71 * p;
q = 1/clip.w; screen = clip.xyz * q (Z * 87.z, min qw1.y in the CA90 family);
fog = clamp(40.x + 40.w * clip.w, 40.z, 40.y); STQ = (u q, v q, q); RGBA = min(c, qw39).
Output packet: A+D PRIM (header .x: 3 list, 4 strip) and PRMODE (87.x), then
NLOOP x {STQ, RGBAQ, XYZF2} (ADC on vertices the program does not draw), plus a one-register
A+D packet (FOGCOL from qw41).

## Constants from the game (slice 1)

`src/native/render/nr_const.[ch]`, `nr_scene.c` (`game_constants`). A record's constant block
(VU qw 0-111 and the bone rows 768-899) is filled at record time, on the EE thread, from the
packets the game's builders have just written; VU memory is not read. Every writer of the
block is a fixed-layout builder (STCYCL 1,1 + UNPACK V4-32 + data, `RET`-terminated):

| qw | builder | how the record finds it |
| --- | --- | --- |
| 0-19 | `CameraWriteViewPacket_148740` | sorted path: the node header's view packet (`r100`); unsorted: the context's current view packet (ctx +0x36B0). Since 2026-10-26 applied from the copy written at that address for that context (override: `nr_note_view`; see "Remembered packets") |
| 24-28 | `DrawPktBuildCameraMatrix_1486c0` | the packet the context built last (override notes it: `nr_note_cammtx`; applied from a copy taken then) |
| 30-51 | `LightStateWritePacket_1484a0` | sorted: the node header's light packet (`r110`); unsorted: `LightStateGetPacket_1428f0`, else the context's last light packet (override: `nr_note_light`). Applied from the copy written at that address for that context (see "Remembered packets" below) |
| 30-40 (shadow volumes) | `DrawPktBuildPlaneShadowMtx_147eb0` + light packets | the context's running light region: every light and plane packet applied in build order (override: `nr_note_plane`); the per-object plane packets rewrite 30-34 only and leave the pass's register packets at 35-40 |
| 60-63 + MSCAL 0 | `VifPktUploadMatrix_148440` (item +0x14) | the draw item's packet; MSCAL 0 runs `nr_const_prog0` |
| 76-79, 81, 42 | the model's `v14` (`ModelMeshWriteVuHeaderMaybe_15b1d0`, ...; item +0x18) | the draw item's packet |
| 768+ | `ModelBuildSkinMtxPacketMaybe_150390` (item +0x1C) | the draw item's packet |
| 82-88 | `MeshMaterialBuildPkt_14ac90` (REF'd), `TexEnvBuildDmaChainMaybe_14abb0` | the mesh's texture/material packet (`DrawListWriteTexEnvPacket_148370`) |

**Remembered packets (2026-10-25, the 1025b shop-close crash; 2026-10-26 rpkt).** The port remembers packets by
address and applies them at record time; the PS2 uploaded them to VU memory once and never read
them again, so their memory (a frame's packet stack, a menu's draw context) gets reused. The
request's light packet is the light record's "emitted" mark (+4, set by `LightStateEmitOnce` /
`LightStateResetEmit`): a record that stays current while its context does not draw (the field
context during a shop menu) keeps a pointer into a stack the menu has reused, and walking it
followed a garbage REF tag to 0x3F800000 (the float 1.0). Now every camera / light / plane packet
is copied when its builder writes it (one inline `RET` block, `nr_const_inline_bytes`), lights
and (since rpkt) view packets also by address (`g_lpk`, `g_vpk`, 256 each), and records apply the
copies (`nr_const_apply_inline`); an unknown request light / view packet is read in place only when
it is still one self-contained `RET` block, else the context's last light packet is used (a view:
none, the record fails `no view`). Identical output in normal play (the copies equal memory);
`RG_NR_STALE=1` counts and prints uses whose memory changed, `RG_NR_NOTE_COPY=0` is the old
behaviour (A/B). Regression: `tools/fixtures/shopcrash.py` (ctest `fixtures.shopcrash`,
play-test gate `shop`).

The sorted path (rpkt, closed): `ModelQueueSortedPackets_14f0d0` writes the view (`r100` = ctx
+0x36B0) and light (`r110` = the +4 mark) addresses into every node header, and
`DrawListEmitBucket_1405a0` CALLs both from the frame chain (`nr_fx.c` walks it; on the PS2 VU1
got them), so the chain followed the same stale marks. `nr_chain_packet(ctx, kind, pkt, dst)` (the
override calls it when it writes the header) resolves them by the records' rule: memory still equal
to the copy (normal play) = the address unchanged (chain, VU memory and run hash unchanged); else
the copy is written into the frame's packet stack at the header and the node CALLs that (one copy
per context, packet and frame); unknown and not a self-contained block = an empty `RET`.
`RG_NR_STALE=1` prints each substitution, the stats line `native render constants notes: request
view packets ...; sorted-chain packets view N (copies, empty) light N (...)` counts them.

Every walker of game memory (`nr_const.c`, `nr_fx.c`, `nr_mesh.c`, `nr_im.c`) translates through
`nr_game_ptr` (`nr_mem.[ch]`): null / scratchpad as before, and on Windows an address that is not
committed readable memory (VirtualQuery, regions cached per thread until the next frame) is refused
like any other unknown layout instead of faulting (a garbage `REF` to 0x3F800000 now fails the walk;
`native render game memory: N walker reads refused` in the stats). Inline payloads and `REF`
ranges are checked too. With this, `RG_NR_NOTE_COPY=0` no longer crashes the shop route; the A/B
now shows as refused reads / poisoned reads instead.

**Poison mode** (`RG_NR_POISON=1` report, `=2` abort): `DrawListFrameBegin_1425d0` (override) fills
the frame packet stack's dead contents with a poison qword (`nr_poison_stack`, `NR_POISON_W*`)
before `MemStackReset`, and every walker checks the tags / payload heads it reads
(`nr_poison_check`): a renderer read of a packet the game has already reset prints `nr: POISON:
<reader> read a dead packet at ADDR` (mode 2 aborts there, so the crash report names the reader)
and counts in `native render game memory: ... poison mode M: Q qwords poisoned, R poisoned reads`.
The game's own reads of dead memory see the pattern too, so poison runs are diagnostic (run hash
not compared). Poison only sees dead memory the game has not rewritten yet: in the 1025b case the
menu had already written its own packets over the field's stack, so that walk reads live-looking
data and is caught by the `nr_game_ptr` refusal instead (the control below: 0 poisoned, 4 refused
reads). Driver `tools/fixtures/poisoncheck.py --exe EXE --suite shop,boot,drivers,soak`
(PASS = the suites pass, 0 poisoned and 0 refused reads, the poison armed), `--control` =
`RG_NR_NOTE_COPY=0` under poison, which must report poisoned or refused reads; ctests `fixtures.poison` (shop, mode 2) and
`fixtures.poison_control`. Audit tool: `tools/native/gameptr_census.py [--check]` lists every
`host()` (must use `nr_game_ptr`), every raw cast of a game address (allowlist with the reason it
cannot read dead memory) and every in-place `nr_const_apply` (ctest `native_only.gameptr_census`).
Still read in place at record time (live when read, the game builds them for the draw): the item
packets (object matrix, model info, skin: node header +8..+16, `d->f14/f18/f1C`) and the mesh's
material packet (`tbl->addrs[]`); the poison runs found no stale read of them.

`nr_const_apply` walks one such packet (CNT/REF/CALL/RET/END tags, the VIF words in the tags
and payload) and applies only what the builders emit: NOP, STCYCL (CL = WL), UNPACK V4-32 to
the block or the bone rows, BASE/OFFSET/ITOP/FLUSH*/MARK/MSKPATH3 (ignored), DIRECT payload
(skipped: GS state, not constants), MSCAL 0. Anything else (other UNPACK formats, masks,
TOPS-relative addresses, other MSCALs) fails the scan and the mesh stays emulated (2 model
items on the golden route). Meshes of one item share the item part (cached by the six packet
addresses); the material packet is applied per mesh.

The VU1 program at address 0 (uploaded at run time, not a retail MPG; listing from
`rg-nr-vutrace C_v24804.vifcap --dis 0-320`), run by MSCAL 0 after every object matrix:

```
R0..R3 = qw60..63 (object rows), V = qw24..27, P1 = qw4..7, P2 = qw8..11, L = qw30..32 (columns)
qw64+i = (Ri.xyz * ERLENG(Ri), Ri.w)               i = 0..2 (normalised rotation)
qw68+i = P1 * (V * Ri)     qw72+i = P2 * (V * Ri)  i = 0..3 (screen, clip matrices)
qw100+i = L * qw64+i.xyz                           i = 0..2 (light directions in object space)
qw111.z = (R0 x R1) . R2 < 0 ? -1 : +1             (the MAC sign flag of x after addy/addz)
```

`nr_const_prog0` evaluates it with the VU's arithmetic (double, chopped toward zero; MADD =
chop(acc + chop(a*b)); the program's operation order): with IEEE rounding a sky dome whose
position cancels the camera translation came out 1 ulp off in qw71 (0.5 px); with the VU
arithmetic every compared qword is bit-identical.

`RG_NR_CONST=game` (default) | `check` (the VIF1 tap compares, at each marker, every qword
lane the native pipeline reads with VU memory; per group counts and a PASS/FAIL line) |
`tap` (the old transition path: constants snapshotted from VU memory).

**The VIF/VU1 no longer see native meshes** (native mode, game constants; `RG_NR_LAZY=0`
reverts): the draw list sends an item's packets (object matrix + MSCAL 0, model info, skin)
only before its first emulated mesh, and skips the microcode uploads (`DrawCtxAddChangedCallTags`)
of native meshes, so VU1 runs nothing for them; in the sorted path "changed" header slots are
judged against what was last emitted per slot. What still passes the VIF for a native mesh:
its texture/material packet (GS state the marker needs, via DIRECT; it carries the 2 small
material UNPACKs) and the marker itself.

One exception stays on the VIF side until its consumer is native: the Z-scale output pieces'
screen bbox in VU qw98/99, consumed by the emulated offscreen-composite program (D_00445C60);
the VIF1 tap merges it when the marker passes (from the record's game constants, nothing is
read). Without it the composited characters vanish (`RG_NR_BBOX=0`: fields 8150/8290 at PSNR 16).

## Shadow volumes (slice 2, first part)

`src/native/render/nr_vu1sh.[ch]` (reference semantics, VU-exact), `nr_scene.c` (`shadow_faces`,
`draw_shadow`). Retail head 0x4425F0 (VuMicrocodeTableInit row 4, material kind 4) with its main
piece 0x4427E0 at 0x10E0 and the decode pieces 0x43A020 (skinned, positions/normals/UV,
1/2/4-bone paths) or 0x4392C0 / 0x439F90 (rigid): the characters' plane shadows, drawn as
shadow volumes into the frame with +1/-1 colour blending.

Per source triangle (vertices three at a time): world = R * p; if dot(qw34, (w1-w0) x (w2-w0))
> 0.0001 (faces the shadow light): A = C * world, B = C * (M * p) with C = (qw8..11 * qw24..27,
xy scaled by qw16.xy) and M = qw30..33 * R (the plane projection); skip the triangle when any of
the six clip vectors is outside |w|; project with S = qw12..15 (x of qw12 * qw16.z, y of qw13 *
qw16.w), Q = 1/w; draw five 4-vertex fans: A0 B0 B1 A1, A1 B1 B2 A2, A2 B2 B0 A0, A0 A1 A2 A2,
B2 B1 B0 B0. Before each fan the program kicks the register packet at qw38 when the fan's screen
cross product has z > 0, else qw35 (`DrawPktBuildPlaneShadowMtx_147eb0`: A+D ALPHA_1 = 0x48
(Cs-0)*As+Cd at 35, 0x42 (0-Cs)*As+Cd at 38, PACKED RGBAQ 1,1,1,0x80); fan packets: PRIM 5,
PRMODE qw87.x, XYZF2 only (ftoi4; W's bit 15 = ADC).

Native: the faces are generated on the GS thread at the marker (`shadow_faces`: positions
decoded VU-exactly from the mesh cache, skinned with the record's bones) and handed to the GPU
renderer's GS draw path (`gs_draw_kick` between `gpu_nr_prims_begin/end`): same batching,
blending (ordered where needed), depth and coherence as emulated primitives, but always
through float interpolation and the hardware rasterizer (no exact evaluation). The register
packets are parsed from the record's qw35/38 exactly as kicked (A+D ALPHA/TEST/RGBAQ, PACKED
RGBAQ; anything else stops the mesh: 0 on the golden route) and left in the GS registers as
the program would.

Batching: the faces alternate between the two ALPHA writes, which split the GPU renderer's
batches at nearly every face (671,442 draw calls to field 13,010). The second ALPHA is the
first with its A and B selectors swapped, so the renderer keeps the register and flags the
face's primitives (`gpu_nr_prims_alpha_swap`, vertex flag bit 7; `gs_draw.hlsl` swaps A and B
per vertex: blending is done in the pixel shader on every path, ordered or snapshot). Primitive
order is unchanged, frames are bit-identical to the unbatched path (fields 8150, 12100,
12500, 13000), draw calls 671,442 -> 27,004 and their GPU time 3.66 -> 0.69 s over the run.
`RG_NR_NOSWAP=1` turns it off.

decode 0x43A020 (skinned) on the golden route: thin strands (hair/fur, grass-like lines), the
largest remaining VU1 program after slice 1 (79 % of the VU1 time left in the town, 70 % in the
battle). Each record is a screen-space segment drawn as four GS lines offset by +-hw in x and
in y (PRIM 1 = line, attributes from PRMODE qw87.x; GIF loop of 9 registers: PACKED RGBAQ
(16, 16, 16, alpha) + 8 XYZF2: a+(hw,0) b+(hw,0) a-(hw,0) b-(hw,0) a-(0,hw) b-(0,hw) a+(0,hw)
b+(0,hw)). The batch header's .x picks the layout: 0x13 = four vertices per record, segment
P1 -> P2, not drawn (ADC on all eight vertices) when P1 or P2 is outside the guard band
(qw109 = qw17.xy * qw16.xy, qw110 = qw18, written by the head) or the strand folds
(((s1-s0) x (s2-s0)).z * ((s2-s1) x (s3-s1)).z < 0); otherwise two vertices per record,
segment P0 -> P1, guard band only. fade = clamp(1.11111 - 0.00277778 * w, 0, 1) from the
segment's first vertex, alpha = int(64 fade), hw = 0.5 fade. The ADC word is 0xFFFF8000
(MFIR sign-extends vi01 = 0x8000). Level 1: C_v24804 102 runs (97 four-vertex, 5 two-vertex),
623 records, all bit-identical; control `--control 6` fails. Native: the records are generated
on the GS thread from the mesh cache's vertices (the decoder keeps batches with the layout
codes 0x11/0x13; it builds no triangles for them) and handed to the GS draw path as lines
between `gpu_nr_prims_begin/end`.

## Frame list (slice 4: the retained boundary)

`nr.h` "frame list", `nr_scene.c` (`frame_add`), override `DrawListFrameBegin_1425d0.c`
(`nr_frame_begin` numbers the frames). Per game frame the GS thread collects the native draws
in the order it executes them (the game's DMA order: sorted buckets resolved), each item
holding everything needed to draw it again without the game:

| field | content |
| --- | --- |
| `mesh`, `variant` | the decoded mesh (immutable vertex/index arrays, GPU copy keyed by `mesh->id`) and the program variant (`NRV_*`, incl. shadow volumes) |
| `c`, `bones` | the record's constant block: the builders' source values (camera view qw0-19 = projection/screen, camera matrix 24-28, lights 30-51, object matrix 60-63, model info 76-81, material 82-88) plus what `nr_const_prog0` derived from them (64-75, 100-102, 111) and the bone rows |
| `src[8]` | the builder packets the constants came from (context, view, light, object, info, skin, material, microcode list) |
| `gs[NRF_*]` | the GS state the draw used: FRAME, ZBUF, TEST, ALPHA, TEX0/1, CLAMP, PRMODE, XYOFFSET, SCISSOR, FBA, FOGCOL, TEXA, PRIM, and (for the replay) PRMODECONT, PABE, COLCLAMP, DTHE, DIMX, SCANMSK, MIPTBP1/2 |
| `has_box`, `box` | the screen rectangle the mesh can touch |
| `texkey` | the decoded texture the draw sampled (renderer cache key: registers, CLUT content, content of the pages read) |

`nr_frame_last()` is the last completed frame (valid until the 4,096-record ring wraps, about
ten frames). `RG_NR_FRAMEDUMP=N` prints frame N's list.

How the two goals use it (next steps, not done):

- **Unlocked frame rate**: render frame k's list again at intermediate times. Because the
  derived constants are recomputed from source values by `nr_const_prog0`, interpolation
  works on the sources: object rows (qw60-63) and bone rows between frames k-1 and k, the camera
  (24-27, and 0-19 when the projection changes), then derive. What the item still lacks is a
  stable identity across frames (`src[]` are per-frame packet addresses): the draw request's
  object (`ModelPrepareDrawMaybe_14f760`'s `obj`) and mesh index, to be added to the record in
  the two front-end overrides. Re-submitting with the item's own GS state is done
  ("Replay": `gpu_nr_replay_draw`).
- **Widescreen stage 2**: the projection lives in qw4-11 (from `CameraWriteViewPacket`); a
  widened projection is a different view block, the rest of the item unchanged.
- Until every category is native, a frame also contains emulated primitives between the
  items (2D, effects, remaining VU1 programs); a retained re-render of the whole frame needs
  those native too (slice 3).

## Replay: the frame list drawn again (slice 4, second half)

`nr_scene.c` (`frame_replay`), `gpu_core.cpp` (`nr_fill`, `gpu_nr_replay_*`). The proof that
the frame list is a self-contained retained boundary, the base of the unlocked frame rate:
`RG_NR_REPLAY=N` draws every completed frame list N more times, without the game, into an
offscreen colour + depth pair (not a GS buffer: nothing the game, the GS model or local memory
can see), each item from its own data only:

- the decoded mesh, the constant block and bone rows (`build_cb_cv` on the item's `c` /
  `bones`), culling from the item's variant and handedness;
- the GS state from the item's registers: the frame item now keeps everything a native
  draw's pipeline reads (`NRF_*` adds PRMODECONT, PABE, COLCLAMP, DTHE, DIMX, SCANMSK,
  MIPTBP1/2); `gpu_nr_replay_draw` puts them at their GS addresses over a scratch copy of
  the GS state and runs the same `make_key` / `derive` / `nr_fill` as `gpu_nr_submit`;
- the texture by identity: `texkey` is the decoded-texture key of the original draw
  (registers + CLUT content + content hash of the pages read, `gpu_nr_last_texkey`), and the
  replay samples the renderer's decoded copy with that key (`tex_cached_only`): never local
  memory, which may hold another texture by then (the game re-uploads into a texture pool
  every frame, "Texture uploads").

The target is the frame buffer most items draw into; items drawing elsewhere (the composite's
work textures) are counted, not replayed; shadow volumes and line strands (GS draw path) are
counted too. Each pass is read back and hashed (FNV-64); all N passes must be identical.

## Offscreen composite (slice 3, first part: 0x445C60 native, the VIF bbox tap no longer used)

`nr_comp.[ch]` (the program, VU-exact), `nr_scene.c` (`clip_note`, `nr_clip_reset`,
`nr_comp_sprite`), overrides `DrawListResetClipRangeMaybe_148040.c` and
`ScreenTexOverlayWriteSpriteMaybe_16a890.c` (generated). `ModelDrawOffscreenCompositeMaybe_16aac0`
draws a character part into a work texture with the Z-scale output pieces (the clip range,
ctx +0x3CCC, between `DrawListResetClipRangeMaybe_148040`'s upload of (2^24, -2^24) to qw98/99
and `DrawCtxClearClipRangeSetMaybe_148030`), then composites it back with sprites; each sprite
was a VU1 program run (MPG 0x445C60, 59 instructions at 0x960, MSCAL with qw140-144 = rectangle
min / max, UV offset, XYZ offset, GIF tag) that clips the rectangle to the screen bbox in qw98/99
and kicks it in strips 32 pixels wide (listing and semantics in `nr_comp.h`; arithmetic is the
VU interpreter's bit for bit: operands with exponent 0 read as zeros, chopped results, MAX/MINI
on signed magnitudes, the MAC sign flag of SUB as the loop condition).

Native: the EE side keeps qw98/99 as the draw list builds it (`g_cl`): reset by the reset
override, merged with each native Z-scale record's screen min / max at record time
(`bbox_compute`, the same C math the VIF tap used, now done once per record on the EE). While
every Z-scale mesh since the reset is native, the sprite override gets its strips from
`nr_comp_strips` and emits them as one DMA CNT + VIF DIRECT GIF packet (tag NLOOP n, the
program's register list UV XYZ2 UV XYZ2): no MSCAL, no VU1, nothing read from VU memory. An
emulated mesh inside a clip range (or no reset seen yet, e.g. after a state load) makes the
range unknown: its native records are flagged and the VIF tap merges their stored bbox into VU
memory (a 2-qword min/max, no transform) for the VU program, which then runs. The program
reads the I register left by the previous VU1 program for the second corner's Z / W words
(MAXi before the LOI takes effect); the composite draws with the Z test off and Z writes masked,
so those words change nothing (the EE uses I = 0).

`RG_NR_COMP=native` (default) | `check` (VU program + tap, every kicked strip compared with
`nr_comp_strips`; X/Y/UV/ADC bits, Z/W reported apart) | `off` (VU program + tap always).

## Refraction material (slice 2 completed)

`nr_vu1.h` `NRV_REFRACT`, `nr_vu1.c` (`nr_vu1_vertex`), `nr_draw.hlsl`, the generated variant
test. VuMicrocodeTableInit row 6: head 0x436FB0 (0x436CB0's code with another double-buffer
base and no guard-band set-up), kind 0x43ECD0, output 0x43E380. The kind piece (a software-
pipelined loop, listing in `out/nrender/dis/vu1_43ECD0_39D0_*.txt`) computes per vertex

    c   = qw72..75 (xyw rows) * p            (the clipper's matrix, object -> clip)
    o   = (qw75.x, -qw75.y) / qw75.w         (the object origin on screen)
    uv  = ((c.x / c.w, -c.y / c.w) - o) * qw82.z + o + (qw82.xy - 1) * 0.05 + 1) * 0.5

and the output piece writes STQ = (u, v, 1) (affine in screen space: the shader interpolates
it `noperspective`), RGB 128 (alpha from the colour piece), clamped by qw39, Z scaled and
clamped like the CA90 family (no bbox), fog as usual; its guard-band ADC is left to hardware
clipping like the other variants. The texture is the material's TEX0: the screen copy

Covered: decode rigid / skinned, colour constant / vertex colour (the lights piece would need
more constant rows than `NrCB` has; not seen). `RG_NR_REFRACT=0` keeps it emulated.

## Texture uploads (host->local transfers)

The game re-uploads its textures every frame: ~265 host->local transfers per field in the
battle (CT32 / T8 textures, 16x16 CLUTs), most of them into a texture pool whose slots hold
several textures in turn within one frame (A, B, A, ...), so local memory is genuinely
rewritten. `xfer_row` (the swizzled per-row write into the GS local-memory model) was the
GS worker's largest single cost (30 % of its samples in the battle). Three changes in
`src/ps2/gs/gs_mem.c` (all exact: local memory, hooks order and every game-visible result as
before; `RG_GS_XFER_CHECK=1` compares every block-wise pixel with the per-pixel address):

1. **Staging.** The game sends a transfer as two IMAGE packets (4 qwords, then the rest) or in
   NLOOP-32767 pieces; the data is collected (`gs_xfer_stage_flush`) while nothing else can
   run on the GS (more IMAGE data of the same path follows; any other tag, another path,
   TRXDIR, HWREG or a reset writes what was staged first), so a transfer is handled whole.
2. **Block-wise writes.** A whole transfer aligned to its format's blocks (CT32 8x8, CT16 16x8,
   T8 16x16, T4 32x16: all of the route's) is written block by block, each block 256
   contiguous bytes with one in-block offset table per format (built from `pixel_addr_i`).
3. **Redundant upload elision.** Per 256-byte block a write generation (bumped by the model's
   writes and, through `gs_mem_gen_bump`, by the renderer's write-backs of drawn targets,
   CPU-fallback draws and external writers); a transfer whose bytes hash equal to the last
   completed transfer into the same rectangle, with the generations unchanged and the
   renderer holding nothing newer (`hooks.xfer_clean`), is skipped: no vram write, no
   WRITE_BEGIN/END, so no mirror upload and no texture re-decode. The renderer's WRITE_BEGIN
   of a host->local transfer is deferred to its first data.

`RG_GS_FASTXFER=0`, `RG_GS_ELIDE=0`, `RG_GPU_NO_ELIDE=1` turn them off; `RG_GS_ELIDE_STATS=1`
prints the counters. Golden route to field 9,000: 2,372,279 transfers, 573,184 elided
(669 MB), 1,784,992 written block-wise (3.6 GB), the row path down from 1.96 G to 1.8 M pixels;
run hash and the frame at 8,290 identical with all three off.

What this does not do yet (the design for the next step): the texture pool means the bytes
are needed in local memory only when something reads them (a CLUT load, a local->host or
local->local transfer, or a draw that samples through the mirror). Recording a transfer as a
pending blit (its staged data and content hash) and materialising it only on such a read,
with the native draws' decoded-texture key taken from the transfer's content hash instead of
re-hashing pages, removes the swizzle for every texture that native draws alone sample and
for pool slots overwritten before any read. The block-wise write moved the cost (the
`xfer_image_body` samples are as many as `xfer_row`'s were): the remaining cost is the volume
(~1-2 MB per field), not the address arithmetic. That next step is done: "Lazy transfers" below.

## Immediate packets (slice 3: 2D, HUD, fonts, menus, effect passes)

`src/native/render/nr_im.[ch]`, `gpu_core.cpp` (`gpu_nr_im_submit`), `nr_draw.hlsl` (`VS_im`,
`NRV_IM`), override `gs/DrawListEndPrim_141a20.c` (generated). The game's whole immediate
drawing goes through one API: `DrawListBeginPrim_141b00` hands out a GsPkt builder, the
`GsPkt*` functions write a DMA sub-chain (CNT blocks with VIF DIRECT + GIF packets, CALLs into
static packets, a final RET), `DrawListEndPrim_141a20` CALLs it from the frame's chain. UI,
HUD, fonts, menus, message windows, sprites and the screen-effect passes (`ShadowMapBlur`,
glare / bloom / DOF / composite passes: `DrawListAddEnv` sets their FRAME, the pass itself is a
BeginPrim/EndPrim packet) all come this way (93 % of the packets on the golden route; the rest
upload VU microcode (`MPG`) or are smaller than the marker).

- **EE (record)**: the EndPrim override calls `nr_im_end_prim(packet)`. The sub-chain is walked
  (CNT/NEXT/REF/REFS/REFE/CALL/RET/END, VIF NOP/MARK/FLUSH*/DIRECT, DIRECT data qword-aligned)
  and its GIF packets decoded ONCE into a record in a 32 MB ring: the exact sequence of GS
  register writes the GIF parser would make (PACKED conversions incl. the internal Q, REGLIST,
  the tag's PRIM) and IMAGE data (copied; consecutive IMAGE tags merged so a transfer stays
  whole). The packet's head is rewritten into the marker (CNT + DIRECT, A+D write of
  `id | 1 << 63` to `GS_NATIVE_MARK`, FLUSHA kept when the packet had one) + RET: neither the VIF
  nor the GIF parser sees the packet. Kept as is: packets with other VIF codes (MPG), a GIF
  packet still open at the end, SIGNAL / FINISH / LABEL writes (the GS worker runs those
  synchronously), local->host transfers, heads under 3 qwords.
- **GS thread (run)**: the marker runs the record. State registers go to the GS register file
  (`gs_write_reg`: CLUT loads, transfers and the state later emulated or native draws see stay
  exact); vertex writes build primitives (the GS vertex queue, strips and fans, flat shading =
  the last vertex's colour) batched while the state is unchanged; a batch goes to
  `gpu_nr_im_submit`, which draws it with the native pipeline: `VS_im` (GS coordinates, the
  target mapping of the mesh path, Z as stored, STQ / UV interpolated linearly in screen space
  and divided per pixel like the GS), `PS_nr` (TFX, alpha test, fog, FBA, dual-source blend),
  the decoded texture (content-keyed cache) or a live render target sampled directly (below),
  hardware raster, no depth bias. States it does not draw like the GS (CT16 frames, destination
  alpha test, partial FBMSK, AFAIL, blend C = Ad, COLCLAMP off / PABE / SCANMSK, frame/Z alias,
  texture feedback other than the same buffer, mipmaps, region clamps, Z-format textures,
  points and lines) are handed to the GS draw path (`gs_draw_kick`, exact) primitive by
  primitive, in order. `RG_NR_IM=replay` sends every write through `gs_write_reg` instead (the
  decoder's check: frames, local memory and the run hash bit-identical to `off`).
- **Real render targets for the effect passes**: a texture that is a live colour target (same
  base and width, CT32 / CT24) is sampled directly from the target at the internal resolution:
  no write-back to local memory, no decode. A pass reading the buffer it draws into (glare
  streak accumulation: 24 sprites each adding a shifted copy of the buffer) is split where a
  primitive reads texels an earlier primitive of the batch wrote, and each part samples a copy
  of the texels taken before it (the GS's per-primitive snapshot semantics).
- **Upscaling** (scale > 1, the emulated path's rules): sprites cover whole s x s blocks of the
  pixels the GS draws and take their texture coordinates at the native pixel's centre
  (`PF_SNAP`); a live target is read in native texel units with each tap at the destination
  sub-sample's phase (`PF_SUBPH` point, `PF_NATTAP` bilinear: the game's half-pixel blur passes
  keep their blur, a 1:1 copy keeps the upscaled detail). Point-sampled 1:1 mappings get a
  1/512-texel bias (the GS's fixed-point texel lands exactly on the boundary).

`RG_NR_IM=native` (default) | `replay` | `off`; `RG_NR_IM_DEBUG=N` (the first N batches: state,
first primitive), `RG_NR_IM_EMU=mask` (bisection: leave states to the GS draw path).

## Lazy transfers (texture uploads decoded once, local memory written only when read)

`src/ps2/gs/gs_mem.c` ("Lazy host->local transfers"), `gs.h` (`gs_mem_materialize*`,
`gs_mem_lazy_texels`, `hooks.lazy_ok`), `gpu_core.cpp` (`on_lazy_ok`, `lazy_before_draw`,
`upload_pages`, the texture path of `nr_draw_resolved`). A whole host->local transfer (staged,
one IMAGE run) into a rectangle the renderer holds nothing for (no live target, nothing newer,
no pending batch: `lazy_ok`) is not written into local memory: the model keeps it pending (its
registers, a copy of the bytes, their hash; every 256-byte block it covers is owned by it, at
most one owner per block). It is written (materialized: the transfer replayed through the
normal path with the hooks) only when something needs the bytes:

| reader | how |
| --- | --- |
| CLUT loads, local->host / local->local transfers, a reset | the model materializes the rectangle it reads first |
| a new transfer partly over a pending one | the old one first (older bytes); exactly the same rectangle: replaced (texture-pool slots rewritten before any read cost nothing) |
| an emulated draw | `lazy_before_draw` at the top of `on_draw`: frame / Z pages, the texture's level-0 blocks (mip levels by page) |
| a target bound over pending pages, the display, any page upload | `upload_pages` writes them without hooks (the renderer marks what was written) |
| a native draw whose texture is not in one pending transfer | the blocks of its texture (immediate draws: the texels they read) |
| `gpu_sync` (dumps, save states, detach) | everything |

A native draw whose texture's blocks all belong to one pending transfer (any transfer format:
the game uploads its T8 textures as CT32 rectangles) takes it from there: the content key is
the transfer's bytes and its geometry relative to the texture (not its address, so pool slots
share entries), and on a cache miss the texels are produced by replaying the transfer into a
scratch copy of local memory and reading them back (`gs_mem_lazy_texels`), then CLUT / TEXA
expanded on the CPU exactly like `tex_fetch` and uploaded (`GpuNrDraw.dec_rgba`). Nothing the
game observes changes: every read sees the bytes it would have seen (golden route to 9,010 with
the immediate path off: displays and local-memory dumps bit-identical to `RG_GS_LAZY=0`, run hash
identical). Save states: the store lives in the GS model's heap block; the runtime's pre-save
`gpu_sync` materializes everything first.

`RG_GS_LAZY=0` (off), `RG_GPU_NO_LAZY=1` (the renderer refuses every transfer),
`RG_GPU_NO_LAZY_TEX=1` (native textures never from pending transfers), `RG_GS_LAZY_STATS=1`
(written by cause), `RG_GS_LAZY_LOG=1` / `RG_GPU_LAZY_LOG=1` (misses).

## Lens-flare depth probe (local->host reads without the VIF/FIFO)

`src/sce/graphics/libgraph.c` (`rg_gs_store_hook`), `nr_scene.c` (`native_store`), wired in
`runtime.c`. `sceGsExecStoreImage` (the lens flare's 8x8 Z rectangle per slot, every frame, and

**Probe lag (2026-10-26, real-time play only; NATIVE-THREADS.md "3h"):** the exact read waits on

small Z read (`nr_dev.cpp` `lag_read`: PSMZ*, <= 16 x 16, <= 4 pages) takes a staging copy of its

previous frame's depth; the run hash is unchanged (forced on, power-on to 31,700: `b0632cdfa80153de` = without), every

## Overlap of the main thread and the GS worker

`src/runtime/runtime.c` (`host_half`, `host_needs_sync`, `ov_present_*`), `gs_async.c`
(`gs_async_call`, `gs_async_mark`, `gs_async_wait_mark`), `gpu.h` (`gpu_set_display_regs`).
A field's end no longer drains the GS worker: it waits only until the worker has finished the
previous field (bounded lag: the native record ring, presentation latency). With the
zero-copy window presentation the frame is composed on the worker (`gs_async_call` after the
field's packets, from a snapshot of the PCRTC registers so the EE can keep writing the live
ones) into the shared texture and presented by the next field's `host_half` (one field of
latency). Fields that read the renderer or the GS on the main thread drain as before: display
hash, dumps, shots (the shot field and the one before), census, recording, copy presentation,
graphics-settings changes (`gfx_update` / scale changes drain first). `RG_GS_OVERLAP=0`
restores the per-field drain. Determinism: everything the EE observes already waited for the
worker (`gs_read_fifo`, CSR / SIGLBLID reads, `gs_path_idle`), so run hashes are unchanged
(golden to 9,000: `715877c8f78c2710` in every configuration).

What limits it in the battle: the lens-flare depth probe (`GfxEndFrame_141c20`,
`sceGsExecStoreImage` of an 8x8 Z rectangle per active slot, every frame) drains the worker
inside the step (96 % of the main thread's waits). It reads the Z of the frame just drawn, so
the wait for that frame is inherent; the overlap now lets the next frame's EE work run beside
it, and the read itself is served from the renderer's early copy (`HotRead`). The rest of the
main thread's waiting is the worker being the slower side (GS model, GPU submission, and two
CLUT loads per frame from pages the GPU drew, which read back: ~13 % of the worker in the
battle, a GPU-side CLUT load would remove them).

## Run hash: emu and native runs compare again (step 0 of checkpoint 7)

Checkpoint (6) saw emu and native runs from the same state end with different run hashes in
this tree, even with its features off. Cause: the run hash folds the native kernel's trace
(`ps2k_trace_hash`), and the trace records every DMAC completion raise (`raise 0x101`). The
lens-flare probe's native local->host read (`rg_gs_store_hook`, checkpoint 6 c) skips the two
channel-1 DMA transfers of `sceGsExecStoreImage`, so the native kernel saw two `raise 0x101`
fewer per probe from the first lens flare on (field 12,151 on the golden route). Game state was
not affected: the per-tick timing record (`RG_TIMING`, power-on to 23,000) is equal in every
column except `GfxEndFrame`'s `depth_z` (the probe's Z minimum, renderer-dependent by nature:
native Z is float-interpolated with a 2-unit bias; `verify` reads the emulated Z and matches
emu). Fix (libgraph.c): the native store raises the same channel-1 completions the DMA path
did. Since then emu and native power-on runs end with the same run hash (golden to 23,300:
`ded4059de1aebd59` in emu, native, native with every change below, the native-only exe).
Runs from a fixture state compare only within one render mode (a state saved in one mode
carries that mode's VU1 memory). `RG_HASH_LOG=path` (runtime.c, new) writes the run hash and
its parts (pad reads, audio, display folds, kernel trace hash / count, clock) per field: the
first diverging column says what differs.

`padmc.npad_equiv` (asked about in step 0): see "Verification (7)".

## Hardware register sites (GS privileged, VIF1_FBRST)

## Frame chain walker (`src/native/render/nr_fx.c`)

`Vif1DmaStart_15e070` kicks the frame's chain on channel 1 (tags transferred). libdma's
`sceDmaSend` offers channel-1 chains to `rg_vif1_chain_hook`; the runtime installs the walker
in native mode (`RG_NR_FX=0`: off). It reads the chain once, at the send, like the DMAC
(CNT / NEXT / REF / REFS / REFE / CALL / RET / END, each tag's two VIF words, then its data):
a validation pass (bad / scratchpad address, invalid VIF code, open payload, more than 2^20
tags: the chain goes to the DMAC; 0 of 11,665 chains to 23,300), then the run: DIRECT
payloads in order into one buffer handed to the GS input VIF1's DIRECT feeds (one call per
chain; the data before a VU program start goes first), every other command whole to a
forward sink (default builds: the VIF1 / VU1 models, so VU memory stays exact for a fallback;
native-only: dropped), NOP / FLUSH* dropped. The kernel sees what the DMAC model made it see
(libdma.c `chain_done`): the channel-1 completion, the VIF1 interrupt for the end-of-frame
i bit posted one cycle after the kick (the DMAC's deferral: `Vif1IntcHandler` latches T0
after `GfxEndFrame`'s reset), the modelled cost (0 under the native kernel). The VIF1
end-of-frame handler is therefore called by the native kernel's INTC latch exactly where the
DMAC model put it (a direct call at the walk would run before `Vif1DmaStart` has added the
handler: the latch is what the threads lane's "direct call" needs, NATIVE-THREADS.md section
5). Check: golden to 23,300, emu = native = native-only run hash; 11,665 / 11,665 chains
walked, 1.49 G DIRECT qwords.

## GPU-side CLUT loads (checkpoint 8)

`src/ps2/gs/gs.h` (`hooks.clut_load`), `gs_tex.c`, `src/gpu/gpu_core.cpp` (`on_clut_load`,
`clut_resolve`, `clut_words`, `clut_tex_gpu`), `gpu_d3d11.cpp` (`clut_load_gpu`, `set_clut_part`,
`clut_read`; the CLUT buffer gained a UAV), `shaders/gs_util.hlsl` (`CS_clut`). The GS model asks
the renderer before a CLUT load reads local memory (`hooks.clut_load`). When the palette is one
the GPU drew (the source under a dirty target or the pending batch) and none of its pages holds
bits the CPU wrote since (no split page, no CPU-newer page, no pending transfer), the renderer
draws the pending batch, writes the targets back into the mirror (GPU work) and `CS_clut` does
`gs_tex0_written`'s arithmetic (CSM1 / CSM2, CSA, CT32 halves, CT16) from the mirror into the
CLUT buffer; the model leaves `gs->clut` alone. The CLUT words the GPU wrote stay GPU-owned
until a CPU load writes them (CPU uploads skip them: `set_clut_part`); their generation is
counted by hand (every GPU load = a new generation; the native texture key mixes it in only
for textures that read GPU-owned words); a CPU user of the values (`gpu_sync`: dumps / save
states / detach, a software-rasterized primitive, `RG_GPU_LAZY_CPU` decodes) reads them back
(`clut_resolve`, counted). `RG_GPU_CLUT=0`: the old path; `RG_GPU_CLUT=check`: every GPU load
compared with the model's arithmetic on read-back bytes (`clut_check_bad` in the exit line).

Status: correct but narrow. A first version also took palettes on split / CPU-newer pages
(4,112 of the 4,114 read-backs of a `boot:save2_battle2` run: 16x16 CT32, bp 16181 / 16229 /
16248 / 16254, CSM1) and removed every read-back (38.7 -> 5.0 MB downloaded, read-back wait
0.24 -> 0.001 ms per battle field headless), but the save2 minimap came out with a wrong palette
(3,750: 34.6 dB / 0.36 % bad vs 39 dB): those palettes are uploaded by the CPU into pages under
a target, and the GPU path's mirror for them was not what the model reads (the check mode, which
reads back, cannot see it: its read-back changes the page states the later loads depend on). So
the GPU path is limited to pages the CPU has not touched; on the fixtures that is 52 loads per
run, and the battle's read-backs remain (4,080 per `save2_battle2` run). Next step: replay the
split-page sequence (palette upload into a dirty target's page, then the load) in the gpu
tests to find where the GPU path's mirror differs, then widen the condition again.

## Checkpoint 9 (2026-10-19): every primitive through the native pipeline, battle read-backs gone

Build `build/nrender-i686`, exe snapshots `out/nrender/bin/c9*` (c9base = the session-start tree).
Each part has a switch back to the checkpoint 8 behaviour.

### Split-page CLUT loads without read-backs (block rule)

`gpu_core.cpp` `blk_stale`, `blk_mark`, `blk_current`, `blk_read_current`, `on_clut_load`.
The 4,080 read-backs per `boot:save2_battle2` run were CLUT loads of palettes the CPU uploads
into a corner of a page a render target covers (16x16 / 8x2 CT32 at bp 16181..16254), read while
the target is dirty or its pages are newer in the mirror: the page-level rule (`read_current`)
then reads the whole page back.  Checkpoint 8's "wide" GPU path for them was wrong (the mirror of
split pages is not what the model reads).  Now the renderer tracks staleness of `gs->vram` per
WORD: `blk_stale[16384]` (64 bits per 256-byte block) is set for the blocks of every target
write-back into the mirror (the only GPU write into the mirror), cleared by downloads, and
cleared by complete CPU writes (whole blocks of full-word formats; single words of CT32 / Z32
transfers, so an 8x2 palette in an 8x8 block counts).  A CPU read (CLUT load, local->host,
local->local source) needs no read-back when none of the words it reads is stale and no live
target's dirty rectangle covers its blocks (block -> target pixel rectangle through the inverse
block table, `blk_rect`).  The CLUT hook asks the same rule first: such a palette is loaded by
the model from `gs->vram`, no GPU work.  `RG_GPU_BLK=0`: page rule only; `RG_GPU_BLK=check`:
every block-rule read also read back and compared (`blk check bad` in the exit line).
Check (save2_battle2 to 5,600): 858 block-rule reads, 0 bad.  The exit line `gpu coherence:`
(always printed now) gives downloads, block-rule reads, GPU CLUT loads, pre-warmed meshes.

### Pre-warm of native meshes (PERF-3D "Transition stutter" cause 3)

`gpu_nr_mesh_prewarm` (gpu.h, any thread) / `GpuBackend::nr_mesh_prewarm` (D3D11 device is
free-threaded): when `nr_model_record` (EE thread) meets a mesh decoded for the first time (mesh
ids only grow), its immutable VB / IB are created there; the GS worker's `nr_mesh_get` adopts
them at its next miss.  The first battle frame's mesh uploads (27 at 4,042, 64 at 4,946, 43 at
5,196 on save2_battle2) leave the GS worker, the pipeline's bottleneck: save2_battle2 481
pre-warmed, 0 uploaded on the GS thread.  `RG_NR_PREWARM=0`: off.  (Texture decodes at first use
stay: they are GPU work from the mirror or a pending transfer.)

### Ordered immediate draws (step 4 of the task: blend fallbacks)

`PS_nr_c` / `PS_nr_cz` (nr_draw.hlsl `NR_CROV`): immediate primitives whose state the output
merger cannot express (CT16 frames, destination alpha test, blend factor Ad, partial FBMSK,
AFAIL modes, COLCLAMP off, PABE, SCANMSK, dithering) draw with no render target: the colour
target through its rasterizer-ordered view (u3; GS bytes like the emulated path's
`PS_main_rov`), depth through the zrov view (u2), and the GS pixel back end in the shader
(DATE, A/B/C/D blend with C = As / Ad / FIX, PABE, dither, COLCLAMP, FBA, FBMSK merge in the

### Shadow maps at the internal resolution (shadow bands, 2026-10-26)

USER play-test 1025b/c: "strange lines going through" the shadows.  The characters' soft
shadows in fields and battles are shadow maps, not the shadow volumes above:
`ShadowMapRender_146680` draws the casters into a 192x192 CT32 work buffer (save2: TBP 14336,
TBW 3), `ShadowMapBlur_145b60` blurs it in place (8 bilinear passes at +-0.75 / 1.75 pixel
offsets, sprites cut into 32-pixel strips), then moves the blurred intensity into alpha with
the classic **CT16 channel shuffle**: the buffer viewed as CT16 (192x384), one sprite per 16
columns drawing x [k+8, k+16) from u [k+0.5, k+8.5) (red/green halves -> blue/alpha halves);
one full-screen sprite (512x448 from u, v 0..192, bilinear, ALPHA 0x44) then darkens the frame
by that alpha.

Cause: at internal res x3, x5, x6, ... (`graphics.internal_res = window` picks x3 for the
default 1280x960 window and for 1080p) upscaled sprites evaluate their texture coordinates at the
native pixel centre (`PF_SNAP`) by extrapolating from the sub-sample with `ddx`; the offset is
a non-dyadic fraction of a pixel there, so u came out a few ulps below k + 0.5 and the
shuffle's bilinear (TEX1 linear; on the GS the weight is exactly 0) took 15/16 of texel k and
1/16 of texel k - 1: two halves' bit fields mixed, the alpha of the first CT32 texel of every 8
wrong (mirror dump: 27-43 texels at alpha 0-32 where the red is 130-165).  The full-screen
sprite magnifies 192 texels to 512 pixels: light vertical bands through every shadow-map shadow
(fields, towns, battles).  x1 has no snap; x2 / x4 / x8 offsets are exact binary fractions, so
those scales were clean.  D3D11 and Vulkan alike (one HLSL source).

Fix (`src/gpu/shaders/nr_draw.hlsl` `gs_uv16`): under `PF_SNAP` the bilinear position (texels,
u - 1/2) is taken as the GS's 4-bit sub-texel position, values within 1/4096 texel below a
1/16 boundary counting as on it, in the `PF_GSLIN` and `PF_NATTAP` paths.  x1 is untouched (no
snap).  At x2 / x4 a few bilinear sprites that sit on such a boundary move by at most 8 levels
(save2 3,790 / 3,850: the transporter beams and the compass, 4-5 k pixels at x2, 19-25 k at x4;
the same count with a 1/512 tolerance, so they are exact boundaries, not tolerance effects).
The shadow map's alpha follows its red again at every scale (0 texels off at x3 /
x5 / x6, both APIs), the shadow region at x3 31.31 dB vs x1 (29.52 before).  The oracle twin's
native draws use the same shader.  `RG_NR_UV16=0` (control): the old snap.

The unlocked frame rate of PLAN.md: an opt-in setting, `display.interpolation` (bool, default

How (the header of `nr_interp.h` has the detail):

- **Retained frames.** From each game frame start (`nr_frame_begin`) the recorder wrapped round
  the device backend keeps every command that draws (native mesh and immediate draws with copies
  of their constant rows, vertices and decoded texels, target copies / loads / clears / creates /
  destroys) and a pre-image of every pre-existing target the frame writes; 5 frames are kept.
  Local-memory traffic is not recorded: a replay never touches local memory, so the game's view of
  the device cannot change.

  of one key paired greedily by nearest object position (object translation + first bone row);
  2D / effects: immediate records, by signature (state writes + vertex data) in packet order.
- **Pass.** At a present between phases the frame the display shows (data flow over the recorded
  commands: this game draws frame N into a work buffer that the start of N + 1 copies to the
  display buffer) and every later recorded frame run again from the pre-images, frame N's matched
  mesh draws with constants interpolated toward N from N - 1 (camera / object: rotation slerp,
  scale and translation lerp, projection lerp, derived rows re-derived by `nr_const_prog0`; bone
  matrices likewise); unmatched items, Z-scale composites, 2D and effects as recorded (snap to the
  latest).  A pair jumping more than 48 px on screen takes the camera only; a context where most
  pairs jump is a cut (no interpolation).  Before anything reads or extends the device state the
  saved target contents are put back (`nr_ip_settle`): the run hash cannot see a pass.

### 13a: composite poses (`RG_INTERP_ZSCALE=4`, the new default inside the opt-in feature)

**What stepped.** Checkpoint 12 moved each character with the scene (placement) but drew its parts
as recorded: the pose changed once per game frame.  The characters are composites
(`ModelDrawOffscreenCompositeMaybe_16aac0`, "Offscreen composite"): per call an RGBA-0 sprite clears
the call's predicted box (+ 9 px) in the work buffer W, the call's parts are drawn into W at their
frame coordinates (W and the frame share the GS window), and sprite strips copy the part's actual
box (clipped to the Z-scale bbox) into the frame.  One character is several calls (the hero on the
Salgin walk: 8, body / cape / sword ...), several characters share one W, the calls of a frame
come in any order.

**How** (`nr_iprec.cpp` "composite poses", `place_plan` / `zs_widen`; `nr_interp.c` mode 4):

* A strip group is one call: `groups_of` also records the parts it owns (the mesh draws into W
  since W's last group) and its clear (the last untextured, unblended immediate draw into W before
  them).  A group is **posed** when its parts are all Z-scale meshes (`nr_ip_zs_item`: no screen
  grab of the frame), its clear draws RGBA 0, overlaps its box and is not a full-target clear, and
  it pairs with the previous frame's group of the same key nearest in box (greedy) with a step
  under 15 % of the viewport.
* Posed parts draw with **the bones interpolated and the camera / object rows as recorded** (the
  part stays where this frame put it in W; mode 3's arithmetic), gated per draw by

  **widened** to the union of this box and the previous box moved onto it, + 8 px (the pose between
  the frames lies in it); the clear grows to cover the widened copy (+ 2 px) so nothing stale is
  copied.  Strip texture coordinates follow the draw's own pixel -> texel mapping.
* A group that cannot be posed draws its parts as recorded and is placed by its own pair's
  centres (mode 2, per call instead of per key).  Composite parts no longer take part in a
  context's camera pair or cut test (their constants place them in W).

### 13b: the one-frame display delay (`RG_INTERP_LEAD`, default 0)

(GIF packets into the GS input), CLUT loads (the GPU-drawn ones only partly on the GPU: "GPU-side
CLUT loads"), local->local T8 copies, the lens-flare Z read, the display read-out.

The design for the rest, in the order it can be done (each step gated like the others):
1. Native draw of the generated primitives: shadow fans, line strands, particle quads and the
   composite draw-back go through `gpu_nr_im_submit` (the native immediate pipeline) instead of
   `gs_draw_kick` / the GIF parser; the shadow faces' per-face ALPHA swap becomes two hardware
   blend states (add / reverse-subtract) batched by sign. Removes the GS-exact draw path for all
   of the route's model-side geometry.
2. A native GS state tracker: the GIF packets of DIRECT payloads and immediate records decoded
   at the walker / EndPrim into register writes kept in a small native state block (TEX0/1,
   CLAMP, ALPHA, TEST, FRAME, ZBUF, SCISSOR, XYOFFSET, PRMODE, FOGCOL, TEXA, TEXCLUT, FBA,
   DIMX/DTHE, COLCLAMP, PABE), the source the native draws take their state from (today they
   read `gs->reg`).
3. The texture / target store keyed by GS address without the 4 MB local memory: uploads kept
   as their transfer bytes (lazy transfers already do this) and decoded on first use by format
   (the swizzle as a decode step, not a memory model), CLUT loads from transfer bytes or from
   targets on the GPU (`CS_clut` already does the arithmetic), local->local copies as GPU copies
   or transfer re-keying, the remaining reinterpretations (CT16 blur passes reading CT32 targets)
   as small conversion shaders between real render targets, PCRTC from `nr_hw.c`'s display
   block.
4. `rg_gpu`'s native pipeline (`nr_draw`, the target pool, the texture cache) moved into
   `rg_native_render`, `rg_ps2_gs` / `rg_gpu` into `RG_NONLY_DROP`, `--forbid render` in
   tests/native_only; the oracle twin keeps both.

## Regression: missing map geometry (2026-10-18, map-regression lane)

**Symptom.** ch06_vedan (cyan sky only), ch09_labyrinth (black), ch12_mariglenn /
ch13_mariglenn (black but a sliver of ground): characters, HUD, minimap drawn, the map not,
field and battle (docs/BRINGUP.md 2026-10-18 (f)). Exes: route5 exe2 (17:45), exe3 (18:17),
ovu0 native-before (18:29) / native-after (19:13) all MISSING; the 15:03 exe, retail and the
current tree (build/play-i686, 20:37, after checkpoint 7) DRAW. Detector:
`tools/fixtures/mapcheck.py` (docs/TEST-FIXTURES.md "Map check").

**Root cause (renderer, two parts).**

1. **The mesh decoder rejects these maps.** `nr_mesh.c` requires every UV to fit V2-8
   unsigned (`fits8u`, `nr_vtx.u/v` are `uint8_t`); the map meshes of these areas carry UVs
   outside 0..255 (tiling / repeating textures), so the whole packet is `bad` ("UV not 8-bit
   unsigned", `RG_NR_DEBUG=1`: 34 packets in ch09, 240..16,464 bytes) and every draw of it
   falls back (`fallback: mesh 21780` of 56,925 mesh draws to field 4,710 in ch09; the three
   census tuples with colour piece != the native one: 15,840 / 4,455 / 1,980 draws, 495 / 0 / 0
   native). The other 20 library areas' maps fit the 8-bit range, which is why only these four
   areas showed it.
2. **Fallback meshes are only drawn while VU1 is linked.** The frame chain walker (`nr_fx.c`,
   16:09) in the RG_NATIVE_ONLY builds of 17:45..19:13 dropped all VU work ("VU work dropped
   (no VU1): UNPACK 28,970,924 words, ... VU program starts 200,564"), so the fallback meshes'
   MSCAL never ran = no geometry. Checkpoint 7 hands VU work to the VIF / VU1 models when they
   are linked (`runtime.c vif1_fwd`; stats line "VU work handed to the VIF / VU models"), which
   is the only reason the current tree draws these maps. **Proof on the current exe:
   `RG_NR_VU=0` (VU work dropped again) = ch09 MISSING (detail ratio 0.18), unset = DRAWN
   (1.01); game run hash identical (80f406f543457072) on all four runs.**

So the regression is masked, not fixed: it comes back the moment VU1 leaves the native-only
link (the planned `render` drop set, "Next slices" 6).

**Fixed (renderer lane, 2026-10-18 (8)).** `nr_vtx.u/v` are `int16_t` now (the 4 bytes of the old
`u, v, uv2, uv3`: the vertex stays 28 bytes), the decoder accepts any UV that fits 16-bit signed
(the VU holds the UNPACK result as a 32-bit integer; V2-8 unsigned and V2-16 both fit),
`VS_nr` reads `TEXCOORD0` as `R16G16_SINT` and scales by 1/32768 x qw79 exactly as before
(ITOF15 input), so values outside 0..255 tile through the sampler's REPEAT like the VU's STQ.
`nr_vu1_vertex` takes `int16_t uv[2]`. Result with VU work dropped (`RG_NR_VU=0`, exe u16):
`mapcheck.py` DRAWN on all five default cards (ch06 1.02, ch09 1.01, ch12 1.04, ch13 1.02,
ch08c 1.00); ch09 `fallback: mesh 0` of 56,925 (was 21,780). The walker now prints
`native render WARNING: N VU program starts dropped ...` at exit when VU work is dropped and
any program start was in a chain (the one-line warning asked for above). Gate: `mapcheck.py
--env RG_NR_VU=0` is part of this lane's image checks from now on.

**Fix (renderer owner):** widen the decoder's UV path: decode UVs as the unpack format really
delivers them (signed/unsigned 16-bit or 8-bit per the batch's UNPACK vn/vl and USN bit), keep
`nr_vtx` UVs as `int16_t` (or float), and scale in `VS_mesh` exactly as the VU program does
(ITOF of the integer UV x the material's UV scale), so values > 255 or < 0 tile through the
sampler's wrap mode (CLAMP register REPEAT). Gate before dropping VU1: `mapcheck.py` (default
cards) with `RG_NR_VU=0` must say DRAWN for all five, and the census of ch09 must show
`fallback: mesh` ~0. Until then, do not drop VU1 from the native-only link, and the walker
should keep counting VU work per fallback mesh (a fallback with no VU1 = a missing draw; a
one-line warning at exit would have made this regression visible in every bootcheck log).
