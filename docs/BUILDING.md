# Building

The game was built with two compilers that only run as old Windows (mwcc) or 32-bit Linux
(ee-gcc) programs. The build runs them -- and the linker -- on a Linux x86-64 **build
host**, and does everything else (assembling the library code, object fix-ups, splitting,
comparing) where the scripts run.

- **On Linux or WSL** the build host is the same machine: set `RGD_HOST=local` and run
  `scripts/setup_toolchain.sh` once. `scripts/localhost/` then stands in for `ssh`/`scp`.
- **From Windows**, point `RGD_HOST` at a Linux machine that accepts `ssh`/`scp` with a key,
  run `scripts/setup_toolchain.sh` there (in a copy of this repository), put the Windows
  decompals binutils in `tools/binutils/` here, and set `RGD_BASH` if `ssh` is not on
  `PATH`.

## Configuration

All machine-specific settings are environment variables, read by `scripts/rgd.py`:

| Variable | Default | Meaning |
| --- | --- | --- |
| `RGD_RETAIL_DIR` | `retail/` | holds `SCUS_974.90` and `BIN/<OVERLAY>.BIN` from your disc |
| `RGD_HOST` | *(required)* | `local`, or `user@host` of the build host |
| `RGD_SSH_KEY` | `.ssh/id_build` | private key for `RGD_HOST` |
| `RGD_REMOTE_DIR` | `~/rgd` | work directory on the host (see below) |
| `RGD_EEGCC` | `$HOME/eegcc` | Sony ee-gcc 2.9 install on the host (see below) |
| `RGD_I386_ROOT` | *(unset)* | `setup_toolchain.sh` only: a private i386 runtime for ee-gcc, if none is installed |
| `RGD_BASH` | *(unset)* | Windows only: a `bash.exe` (e.g. Git for Windows) to run ssh/scp through |

## Build host layout

```
$RGD_REMOTE_DIR/
├── wibo                                  https://github.com/decompals/wibo
└── mwcps2-3.0.1b210-060308/
    ├── mwccps2.exe                       Metrowerks CodeWarrior for PS2 compiler
    └── mwldps2.exe                       Metrowerks CodeWarrior for PS2 linker

$RGD_EEGCC/
├── cc1.sh                                launcher for the 32-bit tools (below)
└── sony29/
    ├── lib/gcc-lib/ee/2.9-ee-991111-01/cc1
    └── ee/bin/as
```

The build creates its working directories (`work*`, `mainlink`, `*lc`, `data2c-*`) next to
`wibo` inside `$RGD_REMOTE_DIR`; the compile commands find the tools as `../wibo` and
`../mwcps2-3.0.1b210-060308/`.

`cc1.sh` runs the ee-gcc binaries, which are 32-bit i386 Linux programs. On a host with the
i386 runtime installed it can simply be:

```sh
#!/bin/sh
exec "$@"
```

Otherwise point it at a private copy of the i386 loader and libraries, for example:

```sh
#!/bin/sh
D=$(dirname "$0")
exec $D/i386/lib/ld-linux.so.2 --library-path $D/i386/lib "$@"
```

ee-gcc is only used for six units of kernel-resident library code (`config/toolchain.txt`).

## Local tools

`tools/binutils/` must contain the decompals MIPS binutils for PS2:
`mips-ps2-decompals-as`, `mips-ps2-decompals-nm` and `mips-ps2-decompals-objcopy`
(with `.exe` on Windows).

## What `scripts/verify.py` does

1. **Main executable.** `hostbuild.py` sends `include/` and every unit in
   `config/units.txt` that has a source file to the host and compiles it with

   ```
   mwccps2 -O4 -c -Cpp_exceptions off -RTTI off -strings readonly -nostdinc -stderr -i include
   ```

   plus the per-unit exceptions in `config/toolchain.txt`. `objfix.py` applies the
   relocation fix-ups listed in `config/objfix.txt`. The data C in `src/main_data/` is then
   compiled with `-sdatathreshold 0`.
2. **Overlays.** `sandbox_build.py` compiles the units listed in
   `config/ocunits/<overlay>.txt` in batches.
3. **Main link.** `link.py` cuts `asm/main.s` into per-function pieces, replaces every
   piece that has C with the compiled object, links with `mwldps2` using
   `SCUS_974.90.lcf`, and compares the result with `retail/SCUS_974.90`.
4. **Overlay links.** `t_olink.py`, `i_olink.py`, `n_olink.py`, `f_olink.py` and
   `x_olink.py` do the same for each overlay and compare the result with
   `retail/BIN/<OVERLAY>.BIN`.

A full build takes a few hours, most of it compiling the ~17,700 units of the main
executable.

## What comes from your copy of the game

The repository carries no game code or data. `scripts/extract.py` (run automatically by
`verify.py` the first time) writes them from the retail files:

- **`asm/`.** The main executable's and the overlays' listings, which the links cut the
  compiled objects into, and which supply the code that is linked as it shipped (the Sony
  SDK, the Metrowerks runtime and crt0). Each is rebuilt from a skeleton in `config/asm/`
  that holds only labels, section directives and row addresses; every row is written as a
  raw `.word`/`.short`/`.byte` of the retail bytes at that address.
- **The values in `src/main_data/`.** The data C was generated by `scripts/data2c.py`
  from `config/data2c.json`. `config/main_data/` holds each file with its values replaced
  by placeholders (names, types, sizes and symbol references stay); `extract.py` fills
  them in from the retail ELF, producing the generated files exactly.

`config/listing_refs.json` holds the gp-relative and jump-table addresses each overlay
function's retail listing referenced, which the overlay links use to place float pools and
jump tables.

Both outputs are ignored by git. Never commit them.
